# RNF-001 — Seguridad

**Tipo**: Requisito No Funcional de Seguridad

## Descripción

El sistema debe cumplir con los controles de seguridad básicos del OWASP Top 10 2021, adaptados
a un proyecto formativo.

## Requisitos Específicos

**RNF-001.1** — Las contraseñas deben hashearse con bcrypt (factor de costo mínimo 12) antes de persistirse.

**RNF-001.2** — Los tokens JWT (access y refresh) deben firmarse con secretos de mínimo 32 caracteres aleatorios, guardados en variables de entorno.

**RNF-001.3** — Los endpoints de autenticación (`login`, `register`, `forgot-password`) deben tener rate limiting (máx. 10 req/15 min por IP).

**RNF-001.4** — Las cabeceras HTTP de seguridad deben configurarse con `helmet` (CSP, HSTS, X-Frame-Options).

**RNF-001.5** — El CORS debe configurar orígenes explícitos — nunca `origin: "*"` en producción.

**RNF-001.6** — Toda consulta a la base de datos debe hacerse con Prisma ORM — nunca SQL crudo con interpolación de strings.

**RNF-001.7** — Ninguna clave de servicio externo (API de mapas, credenciales SMTP, secretos JWT) puede escribirse directamente en el código — siempre debe leerse de una variable de entorno.

**RNF-001.8** — Un cliente nunca puede consultar, modificar o cancelar datos de otro cliente (mascotas, citas, reportes, pedidos) — todo acceso se valida contra el `clientId` del token, nunca contra un parámetro de la URL.

# RNF-002 — Rendimiento

**Tipo**: Requisito No Funcional de Rendimiento

## Requisitos Específicos

**RNF-002.1** — El endpoint de login debe responder en menos de 500ms en condiciones normales.

**RNF-002.2** — El pool de conexiones PostgreSQL debe configurarse con mínimo 2 y máximo 10 conexiones.

**RNF-002.3** — El frontend debe cargar el bundle inicial en menos de 3 segundos en una conexión de 10 Mbps.

**RNF-002.4** — La consulta de agenda del día (RF-017) debe responder en menos de 1 segundo, incluso con varios meses de historial de citas acumuladas.

# RNF-003 — Mantenibilidad

**Tipo**: Requisito No Funcional de Mantenibilidad

## Requisitos Específicos

**RNF-003.1** — El código debe pasar ESLint sin errores antes de cada commit.

**RNF-003.2** — Todos los tipos TypeScript deben ser explícitos — no usar `any` sin justificación documentada.

**RNF-003.3** — Cada archivo nuevo debe tener cabecera de documentación (¿Qué? ¿Para qué? ¿Impacto?).

**RNF-003.4** — La cobertura de tests debe ser mínimo 60% en los módulos de lógica de negocio (RF-009 a RF-023) — un porcentaje ambicioso pero realista para un equipo que recién está aprendiendo a escribir tests.

# RNF-004 — Usabilidad y Accesibilidad

**Tipo**: Requisito No Funcional de Usabilidad

## Requisitos Específicos

**RNF-004.1** — El contraste de color debe cumplir WCAG 2.1 AA (mínimo 4.5:1 para texto normal), en especial en los colores del semáforo (verde, amarillo, rojo), que no deben depender solo del color para transmitir su significado (deben llevar también texto o ícono).

**RNF-004.2** — Todos los formularios (registro, cita, síntoma, carrito) deben ser operables completamente con teclado.

**RNF-004.3** — Los mensajes de error deben anunciarse con `role="alert"` para lectores de pantalla.

**RNF-004.4** — El diseño debe ser responsive — funcionar correctamente en viewport de 320px a 1920px, ya que se espera que la mayoría de clientes usen el celular para agendar.

**RNF-004.5** — Los textos de la interfaz deben estar en español, dado que el público de GroomingSpa es local.
